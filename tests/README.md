# dedit 自动化测试（Level 2 + Level 3）

一条命令跑完全部测试：

```bash
bash tests/run_tests.sh
```

在任意目录下运行都可以。脚本会自动完成：编译（在临时目录里编译，不动 build/）→ 逐个执行 29 个用例（66 项检查）→ 输出 PASS/FAIL 明细 → 汇总。任何用例失败时脚本退出码为 1，全部通过为 0（方便以后接入 CI）。

## 输出示例

```
PASS: TC01 打开文件直接退出（退出码 0）
PASS: TC01 文件内容没有被改动
...
PASS: TC29 显示重做提示（屏幕出现 "Redo"）
==============================
共 66 项检查：PASS=66 FAIL=0
全部通过
```

失败时会给出「期望 / 实际」的详细对比。

## 为什么这样测（原理）

dedit 是全屏 ncurses 程序，必须连接一个"终端"才能运行——直接往管道里喂按键会失败。所以每个用例：

1. 在隔离的临时工作目录里准备输入文件（用例之间互不影响，跑完自动清理）；
2. 用 `script` 命令给 dedit 分配一个假终端（pty）；
3. 等程序启动后，按时间注入按键序列（字节级模拟真实用户敲键）；
4. 断言三样东西：
   - **文件内容**（退出后检查编辑/保存是否正确）；
   - **退出码**（正常退出 0，错误路径 1）；
   - **屏幕上出现过的关键文字**（如 `Modified`、`Saved.`、`Search:`、`No more matches`、`Copied 3 char(s)`，从伪终端录制输出里查找）。

### 两个踩过的坑（也因此成了测试技巧）

- **Esc 键需要"静默间隔"**：Esc 的字节是 `\033`，终端要等一小段"安静时间"才能确认它是 Esc，而不是组合键序列（如方向键）的开头。所以 Level 3 的用例把按键**分块发送**（`run_editor_chunks`，块间隔 0.35s），模拟真人打字节奏；如果一口气把 `<Esc>` 和后面的键挤在一起发，Esc 可能被误读成 Alt 组合键。
- **ncurses 是增量绘制**：屏幕上没有变化的部分不会重新输出，所以录制的字节流里**不一定有连续整串文字**。比如逐字输入搜索词时，流里不会出现完整的 `Search: world`（只有 `Search:` 和随后逐个补上的字符）。断言就找两类东西：一是必然完整出现过的短串（`Search:`、`No more matches`、`Copied 3 char(s)`）；二是构造"两帧内容差得足够多"的场景，让状态栏整行重画（TC27/TC28 检查 `Redo` 前特意按了一下方向键，就是为了让上一帧先回到普通状态栏）。

## 按键记法对照

用例步骤用题目约定的记法描述，脚本里映射为下列字节（在 run_tests.sh 开头统一定义）：

| 记法 | 字节序列 | 说明 |
| --- | --- | --- |
| `<Ctrl-S>` | `\023` | 保存 |
| `<Ctrl-Q>` | `\021` | 退出；有未保存修改时需按两次（第二次强制退出不保存） |
| `<Up>` `<Down>` `<Left>` `<Right>` | `\033OA` `\033OB` `\033OD` `\033OC` | 方向键。脚本固定 `TERM=xterm-256color`：xterm 系方向键是 SS3 序列（`\033O` 开头），不是 CSI（`\033[`） |
| `<Del>` | `\033[3~` | 删除光标处的字符 |
| `<Backspace>` | `\177` | 删除光标前的字符 |
| `<Enter>` | `\r` | 换行（拆行 / 加行） |
| `<Esc>` | `\033` | 退出搜索/替换模式；编辑模式下取消选区 |
| `<Ctrl-F>` `<Ctrl-R>` | `\006` `\022` | 进入搜索 / 替换 |
| `<Ctrl-P>` | `\020` | 搜索：跳到上一个候选 |
| `<Ctrl-C>` `<Ctrl-X>` `<Ctrl-V>` | `\003` `\030` `\026` | 复制 / 剪切 / 粘贴 |
| `<Ctrl-Z>` `<Ctrl-Y>` | `\032` `\031` | 撤回 / 重做 |
| `Shift+<Left>` `Shift+<Right>` | `\033[1;2D` `\033[1;2C` | 选择文本（CSI 带修饰参数的序列） |
| `Shift+<Up>` `Shift+<Down>` | `\033[1;2A` `\033[1;2B` | 选择文本。注意：xterm 系终端把这两个映射成"滚动键"（KEY_SR / KEY_SF），程序里当 Shift+上/下 处理 |

## 测试数据集与设计理由

覆盖思路：**正常编辑（移动/插入/删除/拆合行 + 保存）→ 边界情况（空文件、长文件滚动）→ 错误路径（打不开 / 没参数 / 存不了）→ 搜索/替换/剪贴板/撤回的完整交互链**。

### Level 2（TC01 ~ TC13）

| 用例 | 输入数据 | 按键步骤 | 验证点 | 为什么选这份数据 |
| --- | --- | --- | --- | --- |
| TC01 | `hello` / `world` 两行 | `<Ctrl-Q>` | 文件原样、退出码 0 | 最小回归：不操作时程序不得改动任何东西 |
| TC02 | `abc` / `def` 两行 | `<Right><Right>X<Ctrl-S><Ctrl-Q>` | 变 `abXc`；屏幕出现 `Modified`、`Saved.` | 完整编辑链路：移动 → 插入 → 保存 → 退出 |
| TC03 | `abc` | `<Right><Right><Backspace><Ctrl-S><Ctrl-Q>` | 变 `ac` | Backspace 的"行内删除"分支 |
| TC04 | `abc` | `<Right><Del><Ctrl-S><Ctrl-Q>` | 变 `ac` | Del 的"行内删除"分支 |
| TC05 | `hello` | `<Right><Right><Enter><Ctrl-S><Ctrl-Q>` | 变 `he` / `llo` 两行 | 拆行（在行中间回车） |
| TC06 | `aa` / `bb` | `<Down><Backspace><Ctrl-S><Ctrl-Q>` | 合并成 `aabb` | 行首 Backspace 的"合并两行"分支 |
| TC07 | `aa` / `bb` | `<Right><Right><Del><Ctrl-S><Ctrl-Q>` | 合并成 `aabb` | 行尾 Del 的"合并两行"分支 |
| TC08 | 120 行 `L1…L120` | 80×`<Down>` + `Z` + 保存 | 第 81 行变成 `ZL81`；屏幕可见 `L81`、且不得出现 `L82` | 长文件：验证"光标移出屏幕自动滚动"和滚动后编辑位置正确（文件坐标） |
| TC09 | `keep` | `A` + `<Ctrl-Q><Ctrl-Q>` | 文件仍为 `keep`；屏幕出现 `Unsaved` | 未保存退出保护：第一次警告、第二次强制退出 |
| TC10 | 空文件 | `hello` + 保存 | 内容为 `hello` | 边界：空文件编辑，保存时不能多写空行 |
| TC11 | 不存在的文件 | 无按键 | 退出码 1 | 错误路径：打不开必须报错退出 |
| TC12 | 无参数启动 | 无按键 | 退出码 1、屏幕有 `usage` | 错误路径：用法提示 |
| TC13 | 只读文件 | `X` + `<Ctrl-S>` + 两次 `<Ctrl-Q>` | 屏幕出现 `Save failed`；文件原样 | 错误路径：写盘失败必须提示，不能静默丢改动 |

### Level 3（TC14 ~ TC29）

| 用例 | 输入数据 | 按键步骤 | 验证点 | 为什么选这份数据 |
| --- | --- | --- | --- | --- |
| TC14 | `hello world` / `say hello` | `<Ctrl-F>world<Enter>`；`<Esc>` 后输入 `!` | `!` 插到 `world` 前面；屏幕出现 `Search:` | 用"后续编辑落在哪"证明光标真的跳到匹配处，而不只是看提示文字 |
| TC15 | `ab ab ab`（三个匹配） | `<Ctrl-F>ab<Enter>`×4，`<Ctrl-P>`×3，`<Esc>X` | 走完三个候选；到尾提示 `No more matches`、到首提示 `No previous match`（不回绕）；最后停在第一个候选前插 X | 三个匹配刚好能走出"下一个 / 上一个 / 两端到头"的全部分支；"不回绕"是题目明确要求，必须专门验证 |
| TC16 | `abc` | `<Ctrl-F>zzz<Enter><Esc>Y` | 提示 `No match`；随后编辑正常 | 错误路径：搜不到不能崩，也不能吞掉后续按键 |
| TC17 | 120 行 `L1…L120` | `<Ctrl-F>L100<Enter><Esc>Z` | 第 100 行变 `ZL100`；全程正常退出 | 长文件：匹配在屏幕外，验证搜索会自动滚动到那里（文件坐标仍然正确） |
| TC18 | `foo bar foo baz foo` | `<Ctrl-R>foo<Enter>ww<Enter>`，`Y`×3 | 三处全变 `ww`，提示 `Replaced. No more matches.` | 替换主链路：搜词 → 替换词 → 逐个 Y 替换到底 |
| TC19 | `ab ab ab` | `<Ctrl-R>ab<Enter>XY<Enter>`，`N`，`<Ctrl-P>`，`Y`，`<Esc>` | 第一个变 `XY`；中间跳过；最后不动 | "跳过 / 回退 / 确认"混合操作，验证候选游标前后移动都算得对 |
| TC20 | `x x x x` | `<Ctrl-R>x<Enter>y<Enter>`，`A` | 全变 `y`，提示 `Replaced 4 occurrence(s).` | A（全部替换）分支 |
| TC21 | `aXXbXXc` | `<Ctrl-R>XX<Enter><Enter>`（替换词留空），`Y`×2 | 变 `abc` | 边界：替换词为空 = 删除；不能死循环也不能漏字符 |
| TC22 | `abc` | `<Ctrl-R>zz<Enter>q<Enter><Esc>` | 提示 `No match`，文件不变 | 替换的错误路径 |
| TC23 | `hello` | `Shift+→`×3 选 `hel`，`<Ctrl-C>`，`<→>`×2 到行尾，`<Ctrl-V>` | 变 `hellohel`，提示 `Copied 3 char(s)` | 复制粘贴最小闭环（选区在同一行内） |
| TC24 | `abc` / `def` / `ghi` | `Shift+→`×4（选区 = `abc` + 换行，共 4 字符），`<Ctrl-X>`，`<Ctrl-V>` | 剪切后原地粘贴，文件恢复原样 | 跨行选区"含不含换行"是剪贴板最容易写错的地方；用"剪掉再贴回必须还原"当不变量校验 |
| TC25 | `aaa` / `bbb` / `ccc` | 光标到 (0,1)，`Shift+↓`×2，`<Ctrl-C>`，`<Ctrl-V>` | 3 行变 5 行，提示 `Copied 8 char(s)` | 覆盖 Shift+↑/↓ 选择；纵向跨行粘贴验证多行拆行逻辑 |
| TC26 | `hello` | `Shift+→`×3 `<Esc>` `<Ctrl-C>`；再 `Shift+→` `Shift+←` `<Ctrl-C>` | `No selection` 与 `Nothing selected` 两种提示；文件不变 | 取消选择、空选区两个边界要区分开，且不能把空选区当有效内容 |
| TC27 | `hello` | `Shift+→`×3，`<Ctrl-X>`，`<Ctrl-Z>`，`<Ctrl-Y>` | 剪切 → 撤回 → 重做后文件为 `lo` | 剪切算"一步事件"（题目要求）；撤回/重做的闭环 |
| TC28 | `X`（单字符文件） | 输入 `abc`，`<Ctrl-Z>`×4，`<Ctrl-Y>`×2 | 文件 `abX`；撤回到底提示 `Nothing to undo` | 字符级事件粒度：每个字符一步；撤回到底和重做恢复两个方向都要有 |
| TC29 | `aa aa` | `<Ctrl-R>aa<Enter>b<Enter>`，`Y`×2，`<Ctrl-Z>`×2，`<Ctrl-Y>` | `b aa` | 替换也应作为可撤回事件（题目点名替换 / 剪切 / 粘贴都要能撤回） |

## 怎么新增用例（可扩展）

1. 复制任意一个 `TCxx` 小节；
2. 改四处——名称、输入数据、按键序列、`check` 期望值（Level 3 的用例用 `run_editor_chunks`，把按键按"需要 Esc 的地方"分块）；
3. `bash tests/run_tests.sh` 验证。

Level 4 的测试（CJK、自动缩进等）继续按同样方式在 `run_tests.sh` 里追加。

## 已知限制

- 屏幕内容只做"关键文字"检查，不做逐帧终端画面比对（那需要完整的终端模拟器）；受增量绘制影响，断言要选"必然完整出现过"的字符串（见上文测试技巧）；
- 窗口缩放（改变终端大小）需要真实交互，未纳入自动检查，在手动验收里单独测；
- 等待时间写死（启动 0.5s、分块间隔 0.35s），非常慢的机器上如出现偶发失败，可把 `run_editor` / `run_editor_chunks` 里的 sleep 调大。
