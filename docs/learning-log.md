### 遇到的问题

1. 编译报错：keypad(stdscr, TRUE) 行尾漏写分号。
- 后面还"连坐"出 rows/cols 未定义的错误。
- 解决：从第一条错误开始修，改完重新编译，后续报错自动消失。

2. 分号误打成中文全角"；"，编译器无法识别。
- 原因：中文输入法状态下输入标点，C 代码中所有符号必须是英文半角。
- 解决：改为英文分号；写代码时保持输入法在英文状态。

3. 为什么 load_file 要写在 main 前面？
- 理解：C 编译器从上往下读，函数在被调用前必须先声明。
- 若想让 main 放在前面，需要在文件顶部先写函数声明原型。

4. GitHub 推送失败（TLS 连接中断、提示不支持密码认证）。
- 解决：WSL 通过 Windows 代理访问 GitHub（127.0.0.1:21882）；改用 Personal Access Token 认证并保存凭据。

### 今日收获

完成第一个可交互的终端程序：理解了 ncurses 的屏幕刷新机制与按键处理流程，掌握了 C 语言"先声明后使用"的规则，也学会了用编译器报错定位问题——从第一条错误开始修是最高效的方法。

## 2026/09/26

### 今日完成内容

1. 完成 dedit（Level 2）文本编辑、滚动与保存
- 数据结构：正文用 char lines[1000][256] 的二维数组存（"行的列表"模型），所有编辑操作都按行完成；取舍是写死了 1000 行 × 255 字符的上限，换来实现直观可靠，真实项目应该用动态结构，属于有意做的简化。
- 分清"两个坐标系"：光标记录的是文本中的位置（第 fy 行、第 fx 列），屏幕只是文本的一个窗口（top = 屏幕第一行对应文件里的第几行）；光标移出可视区时自动调 top 跟随。
- 编辑操作：插入字符（memmove 腾位置）、Backspace（行内删字符 / 行首与上一行合并）、Del（行内删字符 / 行尾与下一行合并）、Enter（在光标处把一行拆成两行）；每次操作后把列号夹在行尾之内。
- 窗口缩放：处理 KEY_RESIZE（重新取窗口大小）；因为每帧整屏重画，缩放天然就能正常显示。
- 状态栏（屏幕最后一行，反色显示）：[EDIT] 文件名 | Modified/Saved | 行:列；保存失败时显示具体原因（strerror(errno)）。
- Ctrl-S 保存；有未保存修改时按 Ctrl-Q 先警告（Unsaved changes!），再按一次才强制退出。

2. 为 dedit 搭建自动化测试（Level 2：13 个用例、23 项检查）
- 核心问题：ncurses 程序必须有"终端"才能运行，直接往管道喂按键跑不起来。
- 方案：用 script -qec 分配伪终端（pty）；按键按时间注入：( sleep 0.5; printf '按键字节'; sleep 0.5 ) | timeout 15 script ...。
- 断言三类：退出后的文件内容、退出码、伪终端录制输出里出现过的关键文字（Modified / Saved. / Unsaved / Save failed）。
- 用例之间相互隔离：每个用例独立临时目录（mktemp -d），脚本退出自动清理（trap）。
- 固定 TERM=xterm-256color、按键字节显式定义，保证在任何机器上跑结果一致。

3. 完成 dedit（Level 3）搜索 / 替换 / 剪贴板 / 撤回
- 模式状态机：编辑 / 搜索 / 替换-输入搜索词 / 替换-输入替换词 / 替换-逐个确认，共五种模式；同一批按键在不同模式下语义不同（比如 Enter 在编辑模式是换行，在搜索模式是"下一个候选"）。
- 搜索（Ctrl-F）：状态栏上面一行作为输入行；Enter 找第一个候选（反色高亮、光标跟过去），再 Enter 下一个、Ctrl-P 上一个；不环绕（到尾提示 No more matches、到首 No previous match）；Esc 退出、光标停在当前候选。
- 替换（Ctrl-R）：输入搜索词 → Enter → 输入替换词 → Enter → 逐个替换：Y 替换并前进、N/Enter 跳过、Ctrl-P 上一个、A 从当前候选开始全部替换、Esc 或 Ctrl-C 退出；替换词留空 = 删除匹配。
- 剪贴板：Shift+方向键 扩展选区（Esc 取消选择）；Ctrl-C 复制、Ctrl-X 剪切、Ctrl-V 粘贴；选区统一用半开区间 [起点, 终点)；跨行时行与行之间带上换行；剪切 = 把首尾两段拼接、删掉中间整行；粘贴 = 先把"光标前 + 剪贴板 + 光标后"拼成一条逻辑行，再按换行拆回去、下面的行整体挪位。
- 撤回/重做（Ctrl-Z / Ctrl-Y）：单个字符、退格、Del、换行、剪切、粘贴、替换各算一个事件；用"整篇快照环"实现，最多回退 100 步，产生新动作时丢掉"重做分支"。

4. 测试扩展到 Level 3（共 29 个用例、66 项检查）
- Level 2 的 13 个用例原样保留作为回归测试；新增 16 个用例覆盖搜索、替换、剪贴板、撤回，含错误路径（搜不到、空选区）和边界（替换词为空、不环绕）。
- 新增"按键分块发送"技巧（块之间留 0.35 秒），解决 Esc 的时序问题（见问题 6）。

### 遇到的问题

1. 方向键读回来是一堆数字（258/259/260/261），不是字符。
- 原因：keypad(stdscr, TRUE) 打开后，ncurses 会把方向键的转义序列解析成预定义键码（KEY_UP / KEY_DOWN / KEY_LEFT / KEY_RIGHT）。
- 解决：统一用这些常量做比较；也记下了"真实按键字节 → 键码"的对应关系。

2. 屏幕坐标与文件坐标混用，长文件一滚动就乱。
- 现象：把"光标在第几行"当成"屏幕上第几行"用，短文件看不出问题，换成 120 行的文件一滚动，编辑位置就错。
- 解决：光标只记文本坐标（fy / fx），显示时统一换算（屏幕行 = 文件行 - top）；测试专门用"120 行文件、滚动 80 行后编辑"来验证（TC08）。

3. ncurses 程序在测试里跑不起来。
- 原因：初始化要连接一个终端；从管道喂按键不满足条件。
- 解决：script -qec 分配伪终端；把"按键怎么进去、画面怎么录出来"想清楚，自动化测试就成立了。

4. 方向键的字节序列跟终端有关，写死一种会翻车。
- 现象：有的终端方向键发 \033[A（CSI 开头），xterm 系发 \033OA（SS3 开头）。
- 解决：测试固定 TERM=xterm-256color，按这个终端的真实序列发送；先用探测程序确认了"字节 → 键码"的对应表再写用例。

5. Shift+方向键的键码找不到（为"选择文本"找快捷键）。
- 实验：写了十几行的小程序，把 getch() 返回的原始键码打印出来逐个实测。结果：Shift+←/→ = KEY_SLEFT(393) / KEY_SRIGHT(402)；Shift+↑/↓ 不在 ncurses 常规键表里——xterm 把它们映射成"滚动键"，ncurses 解析成 KEY_SR(337) / KEY_SF(336)。
- 解决：程序里把 KEY_SR / KEY_SF 也当 Shift+上/下 用；"先做最小实验、别靠猜"这个习惯很有用。

6. Esc 键响应慢，而且和组合键有歧义。
- 原因：单独按 Esc 的字节是 27，但所有转义序列也都以 27 开头，终端要等一小段时间确认"后面没有别的字节"才能判定是 Esc。
- 解决：set_escdelay(50) 把等待时间改短；这也是测试里"按键分块发送、块间留静默间隔"的原因——挤在一起发时 Esc 可能被当成组合键的开头。

7. 测试断言"明明屏幕上出现过，却搜不到文字"。
- 现象：搜索时屏幕显示过 "Search: world"，但在截获的输出里搜不到这一整串。
- 原因：ncurses 是增量绘制，只发送"变化的部分"，逐字输入时不存在连续整串。
- 解决：断言挑"必然完整出现过"的短串（Search: / No more matches / Copied 3 char(s)）；或构造"两帧差别足够大"的场景让整行重画（检查 Redo 前先按一下方向键就是这个目的）。

8. 撤回用"差分记录"还是"整篇快照"？
- 分析：差分省内存但容易漏记/记错（特别是替换、跨行剪切）；快照笨重但绝不会算错。
- 决策：先要正确性——选快照（100 步、约 25MB 内存），把复杂度换成可靠；注释里写清楚取舍和真实编辑器的做法，以后有空再升级。

9. 提交里混进了编辑器留下的备份文件（*.save）。
- 教训：提交前先看 git status 确认暂存了哪些文件；.gitignore 不只管编译产物，编辑器临时文件也要考虑。发现后用 git rm 移除并单独提交了一次修复。
